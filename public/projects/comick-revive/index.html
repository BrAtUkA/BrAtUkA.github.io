Why I built it

ComicK is a popular site for finding and tracking manga. When it removed its built-in reader, every chapter turned into a hunt across other sites. ComicK Revive puts a reader back. It adds Start Reading and Continue buttons to ComicK’s own pages, finds the chapter on a source site and opens it right there.

It grew from there. Within three weeks and three releases it became a full app: a dashboard with a library, history, search and stats that works without ComicK at all.

Reading

There are three reading modes: one long vertical scroll for webtoons, single pages, and two-page spreads read right to left. You can switch at any time.

It remembers your place by the image you were looking at, not by how far you’d scrolled. Zoom in, resize the window or change mode, and you’re still on the same panel. Continue takes you back to that exact spot.

Sources

Three sources work out of the box: AsuraScans, MangaDex and MangaKatana. A built-in catalog adds more than 70 others. Switching one on asks for access to that one site only; the extension never gets access to every site. Test all checks each one from your own network and gives you a report you can share.

You can add a site yourself without writing code. A source is a small JSON “recipe” that tells the reader where to find titles, chapters and pages. There’s a ready-made prompt for getting an AI to write one, and a test tool that checks it step by step against the live site.

How it’s built

A browser extension isn’t one program. Its parts run in separate worlds that can’t see each other’s code, and each world can only do certain things. The reader runs inside the ComicK page, so it can draw anything but can’t use the extension’s own APIs or fetch from other sites. That took the most design work.

  • One bridge. The reader and the content script pass messages through a single bridge file, so there is exactly one place where the two worlds meet.
  • Cache first. Before touching the network, a chapter checks whether its pages are already saved. Page lists are kept for a week and images up to a size limit you set, so anything you’ve read before opens instantly and works offline.
  • It fixes itself. If a saved image has gone missing, the reader fetches it again from the source and saves it back, instead of showing a broken page.
  • One engine, many sites. Most catalog sites run the same WordPress theme, so one implementation drives all of them, and adding one is a single line.

What’s left

It’s a beta. Continuous reading from one chapter into the next is experimental and off by default, single and two-page modes are less polished than vertical scroll, and a source can break when its site changes. It runs in Chromium browsers only.
