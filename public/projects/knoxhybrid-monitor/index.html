01Why it exists

Knox hybrid inverters upload their readings to the ShineMonitor cloud every five minutes. The official way to see them is a phone app or a web portal, and both have to be opened on purpose. When the grid goes down the inverter quietly switches to battery, and nothing on the desk says a word.

KnoxHybrid Monitor sits in the Windows system tray instead. It shows the inverter’s state at a glance, raises an alert the moment the house switches to battery, and another when the grid comes back, with how long the outage lasted. It is built for machines that are on all day, so the first rule was that it must cost nothing to leave running.

02How it sleeps

Most monitors poll on a timer: ask the server every few seconds and throw away the answer when nothing has changed. The inverter only reports every five minutes, so polling faster than that only burns battery and API calls. KnoxHybrid Monitor reads the timestamp of the latest reading, works out exactly when the next one is due, and sleeps until then.

The loop has three moving parts:

  • Sleep for the remainder. After a fresh reading, the wait is 300 s minus the data's age, usually 250 to 290 seconds of tokio::time::sleep. The operating system doesn’t schedule the process at all in that time.
  • Retry when the data is late. If the expected reading hasn’t arrived, it checks every 30 seconds for up to ten minutes, then starts over. API errors back off exponentially, from 30 seconds up to five minutes, so a server outage doesn’t turn into a busy loop.
  • Cache with intent. Responses are cached for 240 seconds while data is fresh and only 30 seconds once it is overdue. The device chain (plant, data collector, inverter) is resolved once and kept on disk for six hours.

After every poll it also pre-builds the dashboard’s data, so opening the window is instant and never waits on the network.

03What you see

The dashboard opens from the tray. Five cards cover the essentials (mode, grid, battery, load and solar), an animated diagram shows where the energy is flowing, and below it sit all 22 live readings the inverter reports.

The History tab turns any day into a timeline. Every reading is badged LINE or BATTERY, and a stats bar adds up the outages: how many, how long in total, and the longest one.

04The alerts

The alert is the reason the app exists, so it comes in two forms. A popup is hard to miss, and a compact toast stays out of the way. Each shows the battery level, the load, the grid voltage, when the outage started and how stale the data is. “Don’t Remind” silences repeats until the power is back, and the restore alert reports how long the outage lasted.

Even without opening anything, the tray icon carries the state: green while the house runs on the grid, red on battery.

05Details that matter

  • Credentials stay encrypted. The login is stored with AES-256-GCM, with a key derived from the machine’s hostname, so the file is useless when copied to another PC.
  • The official protocol. It authenticates against the ShineMonitor API the same way the official mobile app does, rather than scraping the web portal.
  • Rust where it counts. The backend (API client, caching, tray, alerts) is about 1,900 lines of Rust on Tauri v2. The interface is plain HTML, CSS and JavaScript with bundled icons and fonts, so it never touches the network for assets.
  • One line per company. Any portal built on the ShineMonitor / Eybond backend can be added with a single line in company_lookup(). Knox is the first; the README walks through adding another.

06What’s next

More companies. The app already speaks the protocol every ShineMonitor-based portal shares, so each new brand is a key and an app ID away. If yours runs on it, an issue on GitHub is all it takes.
